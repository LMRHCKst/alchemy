# Разведка: библиотеки и базы данных

Рабочая справка по `calk` (Alchemy). Не для пользователя — для себя: чтобы не
ходить в поиск заново и не пересматривать уже закрытые вопросы.

Обновлено: 18.10.2026. Проверять раз в полгода, версии устаревают.

---

## Что уже стоит

| Пакет | Версия | Зачем | Обязателен |
|---|---|---|---|
| PySide6-Essentials | 6.12 | интерфейс | да |
| matplotlib | 3.11 | графики | да |
| numpy | — | численные операции | да |
| uncertainties | 3.2.3 | неопределённости с корреляциями | да |

---

## Решение по умолчанию

**Новые зависимости не ставить без конкретной задачи.** Причины:

1. Каждая зависимость — это версии, лицензия, вес в сборке и риск, что
   через год проект умрёт. У `chemicals` 63 зависимости, у `pint` 66:
   это больше, чем весь наш проект.
2. Наши движки покрыты 878 тестами против справочных значений. Пакет,
   который «умеет больше», ещё не значит «считает правильнее» — его надо
   так же проверять.
3. Данные ставим снимком (JSON в `alchemy/data`), а не тянем в рантайме.
   Это уже принятое правило, оно не меняется.

Ставить библиотеку имеет смысл, когда она закрывает то, чего у нас нет
принципиально, а не когда она пишет за нас три строки.

## Рассмотрено и отклонено

### Химия и термодинамика

**chemicals / thermo (CalebBell)** — 1.5.2 / 0.6.1, MIT.
Умеют Joback, UNIFAC, банк свойств, десятки моделей.
Отказ: 63 и 61 зависимость, тянет pandas и scipy. Нам нужны единицы
измерения свойств, а не весь ChEDL.

**thermosteam** 0.54.2 — то же плюс биотехнология, 23 зависимости.
Отказ по той же причине.

**pint** 0.26.1, BSD — 66 зависимостей.
**unyt** 3.1.0 — 3 зависимости, но заточен под numpy-массивы.
Отказ обоих: свой `core/units.py` разбирает «число + единица», проверен
тестами и не тянет numpy-семантику. Пересматривать, только если понадобятся
размерные величины в массивах.

**baLance-rxns** 0.2.0, MIT — уравнивание и поиск возможных реакций.
**reaction-balancer** 2.1.0 — уравнивание и печатные бланки.
Отказ: наш балансировщик решает в рациональных дробях (`Fraction`) и даёт
точные целые коэффициенты, включая строку заряда. Это сильнее того, что
делают оба пакета. Чужой код тут был бы шагом назад.

**pythermocalcdb-nasa** 0.3.0 — полиномы NASA и равновесие.
Отказ: у нас свой снимок на 950 веществ из Burcat и своя интеграция Cp(T).
Дублирование.

**iapws** 1.5.5 — стандарты IAPWS для воды и пара. Лицензия GPL-3.
Отказ: GPL заражает проект. Плюс это узкая область (вода/пар), у нас
есть `liquidvapor.yaml` в Cantera.

**CoolProp** 8.0.0, MIT — база термофизических свойств, 100+ жидкостей.
Кандидат, но не сейчас: нужен для теплоносителей и хладагентов, а не для
школьной и общей химии.

**qcelemental** 0.51.3, BSD — структуры данных квантовой химии, 25 зависимостей.
Отказ: квантовая химия вне задачи.

**AqOrg** 1.1.4, MIT — термодинамика водных органических веществ,
групповая аддитивность, параметры HKF. Группа Шока, ASU.
**ugropy** 3.2.5, MIT — группы UNIFAC из SMILES.
Отказ обоих: это про органику, а её мы сознательно не берём.

**phasepy** 0.0.56, MIT — NRTL, UNIQUAC, Wilson, VLE и LLE.
**vle-thermo** 0.16.0, MIT — 22+ кубических уравнения состояния, VLE.
Кандидаты, если понадобятся фазовые равновесия (перегонка, экстракция).
Сейчас не берём: в школьной и общей химии их нет.

**Reaktoro** — минимизация энергии Гиббса, бэкенды PHREEQC и GEMS.
Отказ: **нет в PyPI**, только conda. Для проекта на pip это стоп.

**pycalphad** 0.11.2, landau — фазовые диаграммы.
Отказ: нужны базы CALPHAD, их нет в комплекте. Задача материаловедческая.

**pymatgen** — диаграммы Пурбе для любого элемента, 27+ зависимостей.
Отказ: у нас есть Пурбе для четырёх систем на своих данных.

**phreeqpython** — PHREEQC целиком, бинарник.
Отказ: у нас свой решатель равновесий с активностями.

**RDKit** 2026.9.1, BSD — SMILES, 2D-структуры, изомерия, дескрипторы.
Отказ пока: единственный реальный путь в органику, но органику не берём.
Если возьмёмся — RDKit первым.

**pyvalem** 2.8.0 — разбор химических видов и состояний.
Отказ: наш парсер понимает гидраты, заряды в трёх записях и комплексы,
проверен против `periodictable`.

### Инструменты разработки

**mypy** 2.4.0 — статические типы. У нас аннотации есть, но проверки нет.
Кандидат низкого приоритета.

## Базы данных

| Источник | Что даёт | Доступ | Лицензия | Годность |
|---|---|---|---|---|
| **NIST-JANAF** | термохимия, Cp(T) | таблицы на сайте | открыто | эталон, берём вручную |
| **Burcat (NASA)** | полиномы Cp(T) | `thermochem` или XML | открыто | **уже взято**, 950 веществ |
| **NIST WebBook** | свойства, спектры | HTML, парсинг | открыто | `NistChemPy` 2.0.0, неофициальный |
| **ThermoML** | термодинамика, стандарт XML | архив NIST | открыто | серьёзный источник для расширения thermo.json |
| **PubChem** | свойства, SMILES, синонимы | PUG REST | открыто | `pubchempy` 1.0.5, есть лимиты |
| **EPA CompTox** | токсичность, Kow, Генри | API | открыто | `scigantic-comptox` 0.3.1 |
| **ChEMBL** | биоактивность | S3-зеркало + DuckDB | открыто | `scigantic-chembl` 0.5.1 |
| **COD** | кристаллография, CIF | REST | открыто | вне задачи |
| **Materials Project** | материалы | API, нужен ключ | открыто с ключом | вне задачи |
| **IUPAC pKa** | 24 211 констант | CSV на GitHub | открыто | **не взято**, кандидат |
| **NUBASE2020 / AME2020** | нуклиды | через `radioactivedecay` | открыто | **уже взято** |
| **GHS** | пиктограммы, H- и P-коды | датасет на HuggingFace | открыто | для безопасности, не для расчётов |
| **IAPWS** | вода и пар | через `iapws` | GPL | не берём из-за лицензии |

### Что именно стоит дозабрать

1. **IUPAC pKa** — 24 211 констант, CSV, открыто. У нас кислоты в
   `acids.json` покрывают школьный и вузовский минимум, но не органику.
   Полезно, если понадобится больше кислот.
2. **ThermoML** — если будем расширять термохимию за пределы 950 веществ.
   Формат XML, стандарт, значения с неопределённостями.
3. **Буферные pKa с dpKa/dT** — сейчас буферы считаются при 298 К.
   Таблицы с производной по температуре попадались, но источник надо
   проверить.

## Открытые вопросы по данным

Из прошлого аудита, ещё не закрыто:

- Cu(OH)₂: ΔG°f расходится с литературой на 8.9 кДж
- K₂Cr₂O₇: расхождение 6.5 кДж
- Пять несоответствий Ksp и термодинамики: ZnS (2.93 порядка),
  Al(OH)₃ (2.14), Cu(OH)₂ (1.96), FeS (0.71), PbS (0.53)
- 43 из 58 значений Ksp не удалось сверить с независимым источником
- Co, Cd, Li отсутствуют в `thermo.json`
- Электродные потенциалы: 26 из 27 сходятся с ΔG°f в пределах 0.05 В,
  расходится только H₂O₂/H₂O (0.058 В)

Вывод из аудита: потенциалы лучше **выводить** из ΔG°f, а не вводить
руками — тогда они не могут разойтись.

## Правила добавления зависимости

1. Лицензия: MIT, BSD, Apache — да. GPL, AGPL — нет (заражает проект).
2. Зависимости пакета: больше 10 — повод отказаться.
3. Данные — только снимком в `alchemy/data`, не запросом в рантайме.
4. Любая новая библиотека приходит с тестом, который сверяет её ответ
   с нашим или со справочным значением.
5. Необязательные пакеты (Cantera, python-docx) должны отсутствовать
   без последствий: программа работает, вкладка объясняет, что ставить.

## Чего искали и не нашли

- Готовая библиотека для школьной номенклатуры неорганических веществ
  (класс + название по формуле). Есть только для органики (OPSIN, RDKit).
  Поэтому `classification.py` свой.
- Готовая библиотека качественных реакций на ионы. Только справочники
  в виде таблиц. Поэтому `qualitative.json` свой.
- Готовая библиотека жёсткости воды по ГОСТ. Поэтому `hardness.py` свой.
- Готовая библиотека степеней окисления с правилами для пероксидов
  и фторидов. Поэтому `oxidation.py` свой.

Это и есть ответ на вопрос «почему столько своего кода»: в прикладной
школьной части готовых пакетов просто нет.
